## 1. 무엇을 · 어떻게
- **문제:** 청음에서 분노A · 기쁨B · 분노B(· 슬픔B) 출력이 "좀 다른 사람"처럼 들렸습니다.
  - 숫자로도 보입니다: 같은 화자의 **생성 중립 평균 ↔ 감정 출력** 유사도가 0.60~0.69 로, 중립끼리(0.79)보다 낮습니다.
- **D안 데이터는 골라 쓰는 데이터입니다.** 그래서 학습 없이 seed 를 여러 번 돌리고 "그 화자다운 것"만 고르면 되는지 봤습니다.
- **입력**
  - D 재측정과 같습니다: `"(v1 지시문)문장"` + 목표 화자 무감정 reference · cfg 2.0 · timesteps 10 · 준비 합성 뒤.
  - 목표 16명, 칸 4개(분노A · 기쁨B · 분노B · 슬픔B), 칸마다 문장 2개(d_eval 과 같은 문장).
- **① 생성:** LoRA01_s1500 · LoRA02iv2_s1500 에서 seed 1986 ~ 1990 을 각각 만들었습니다(모델당 640개).
- **자기 중립 유사도:** 출력과 "같은 모델 · 같은 화자의 d_eval 생성 중립 2개 평균"의 코사인입니다. WavLM-large 와 ERes2Net 값을 평균했습니다.
  - `tools/vspk.py` 와 같은 임베딩입니다. q3tts 세션 표의 값(분노A 0.69 등)이 그대로 다시 나왔습니다.
- **같은 잣대로 함께 잰 것:** 목표 REF 유사도 · 목표 1위(같은 성별 150명 중) · e2v 감정 · arousal · whisper CER · SQUIM · 끝 잘림 · 긴 무음.
- **① 고르기 규칙(V1, 페이지에 쓴 것):** 문장마다 다섯 개 중에서 아래 세 조건을 모두 지킨 것 가운데 **자기 중립 유사도가 가장 높은 1개**를 고릅니다.
  - CER ≤ 10%
  - 이상 없음
  - 감정 있음: e2v 가 그 감정이거나, arousal 이 진짜 녹음 같은 칸의 10~90% 범위 안
    - 범위: 분노A 0.49~0.80 · 기쁨B 0.54~0.80 · 분노B 0.64~0.79 · 슬픔B 0.35~0.74
- **③ 문턱:** 진짜 녹음 16명(vspk 천장)에 같은 구조로 잰 "감정 녹음 ↔ 그 사람 중립 2개 평균" 분포를 기준으로 씁니다. 이 분포의 하위 10% · 20% 값보다 낮으면 버립니다.

  | 묶음 | 평균 | 하위 10% | 하위 20% |
  |---|---|---|---|
  | 기쁨 | 0.700 | 0.576 | 0.629 |
  | 분노 | 0.702 | 0.583 | 0.621 |
  | 슬픔 | 0.659 | 0.533 | 0.594 |

- **재현**
  - seed 1986 출력이 d_eval 합성음과 **256/256 같은 소리**였습니다(두 모델 각 128/128).
  - ② cfg 2.0 도 32/32 같았습니다.
  - 청음 노트북 엔진(`voxko.listen.Listener`)으로 페이지 wav 3개를 다시 만든 결과도 **3/3 같았습니다**(seed 1987 고른 것 2개 · cfg 1.5 1개).

## 3. ② 추론 노브 (LoRA01_s1500 · 목표 4명 × 4칸 × 2문장 · seed 1986 · 각 32개)

- **cfg:** 1.5 는 목소리와 감정이 함께 나빠집니다. 2.5 는 2.0 과 목소리가 같고, e2v 는 +10%p · CER 은 조금 낮습니다.
  - 32개뿐이라 차이가 작다고 봐야 합니다. 바꾼다면 2.5 를 청음으로 확인한 뒤입니다.
- **prompt 모드(요청 그대로)는 쓸 수 없습니다.**
  - VoxCPM2 는 prompt 모드에서 글을 `prompt 전사문 + 문장` 으로 이어 붙입니다(`VoxCPM/src/voxcpm/model/voxcpm2.py:492`).
  - 그래서 `"(지시문)문장"` 을 주면 지시문이 가운데 끼어, **영어 지시문을 그대로 소리 내어 읽습니다**(ASR "…very happy and excited, bright…").
- **prompt · 지시문 맨 앞** 은 `"(지시문)prompt 전사문"` + `"문장"` 으로 준 변형입니다.
  - 목소리는 진짜 녹음 천장(0.70)보다도 훨씬 단단합니다(0.83).
  - 하지만 감정은 e2v 19% · arousal 0.52 로 **거의 중립**입니다. 11/05 M4 시범과 같은 결론으로, prompt 목소리가 감정 지시문을 이깁니다.
- **맞바꿈:** prompt 를 쓰면 목소리 +0.15 와 감정 −40%p 를 맞바꿉니다. D안 데이터(감정이 목적)에는 맞지 않습니다.

## 4. 비용 (생성 시간 배수)
- 생성 속도: RTF 는 단독 GPU 에서 약 0.45, GPU 하나에 세 작업을 함께 돌리면 약 0.9 입니다. 채점(목소리 · 감정 · CER · 깨짐)은 생성의 약 1/3 입니다.
- 남는 문장 하나당 생성 배수:
  - **①(V1) + ③:** 5회 생성 ÷ 남음 87% ≈ **5.7배**
  - **①(V3) + ③:** 5 ÷ 72% ≈ **7배**
  - **1986 하나 + ③만:** 1 ÷ 55% ≈ **1.8배**. 싸지만 남는 것의 유사도는 문턱 근처 그대로입니다.
  - **seed 3개(가늠):** 2~3배 사이에서 효과의 대부분을 얻을 수 있는지는 같은 데이터로 바로 다시 잴 수 있습니다(추가 생성 없음).
- 예: 목표 16명 × 감정 6칸 × 20문장 = 1,920개를 V1 + ③ 으로 만들면 약 9,600회 생성입니다. GPU 1장 단독 기준 약 3~4시간(문장 3초 가정)입니다.

## 5. 결론 · 제안 (청음 뒤 결정)
1. **D안 데이터 생성에 ① + ③ 을 쓰는 것을 제안합니다.** 숫자로는 감정 칸의 목소리가 진짜 녹음 수준까지 올라옵니다.
   - 규칙은 **V1(목소리 우선) 과 V3(감정 지키기)** 중에서 청음으로 고릅니다. 저는 감정이 데이터의 목적이라 V3 쪽을 권합니다.
2. **seed 수(N)** 는 5 로 시험했습니다. 3 으로도 충분한지는 추가 생성 없이 재 볼 수 있습니다(요청하시면).
3. **② 노브**
   - cfg 2.5 는 작은 이득이 있으니 청음으로 확인할 만합니다.
   - prompt 모드는 감정이 사라져 D안에는 쓰지 않는 쪽을 권합니다.
4. 감정이 원래 약한 기쁨B(e2v 9~40%)는 고르기로도 크게 나아지지 않습니다. 지시문이나 학습 쪽 문제로 따로 봐야 합니다.

## 6. 다시 만들기
```bash
cd ~/workspaces/vox_koft
python tools/bestofn.py prep
CUDA_VISIBLE_DEVICES=2 ~/miniforge3/envs/voxcpm/bin/python tools/bestofn.py vox --set bon --tag LoRA01_s1500   # LoRA02iv2_s1500
CUDA_VISIBLE_DEVICES=2 ~/miniforge3/envs/voxcpm/bin/python tools/bestofn.py vox --set knob --tag cfg15          # cfg20 · cfg25 · prompt · prompt_front
for s in bon knob; do
  CUDA_VISIBLE_DEVICES=2 ~/miniforge3/envs/q3tts/bin/python     tools/bestofn.py sv --set $s
  CUDA_VISIBLE_DEVICES=2 ~/miniforge3/envs/q3tts_ser/bin/python tools/bestofn.py ser --set $s
  CUDA_VISIBLE_DEVICES=2 ~/miniforge3/envs/voxcpm/bin/python    tools/bestofn.py quality --set $s
done
~/miniforge3/envs/voxcpm/bin/python tools/bestofn.py page        # report 포함 → bestofn/index.html · tables.md · report.json
```
- 채점은 `voxko/eval/d_eval.py` 의 sv · ser · quality 함수를 그대로 부릅니다. 출력 폴더만 바꾸고 d_eval 파일은 고치지 않았습니다.
