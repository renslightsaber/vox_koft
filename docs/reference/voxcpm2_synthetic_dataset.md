## 1. ① SREF — 서비스 ref 단일 화자 데이터
### 1-1. 가능한가
- VoxCPM2 의 Ultimate cloning(ref 소리 + 그 전사문 + reference)은 ref 목소리를 가장 가깝게 따라 합니다. 지시문 비교 시범에서 서비스 ref 유사도 **0.79**(WavLM-large SV)로, 우리 기준 모델 s2250(0.70)보다 높았습니다.
- 운영 B(VoxCPM2 로 보임)는 고객 검수 run117 에서 코드스위치 문제 0건이었습니다.

### 1-2. 수량
| | 문장 수 | 음성 길이 | 근거 |
|---|---|---|---|
| 최저 | 약 500 | 약 40분 | 커뮤니티: 수십~수백 개로도 목소리 고정. 단 1.5시간 FT 가 zero-shot 보다 크게 낫지 않았다는 보고(Baseten)도 있음 |
| **적정** | **2,000~4,000** | **3~5시간** | 합성 데이터 연구(arXiv 2512.17356): 총 시간이 같으면 **서로 다른 문장이 많을수록** 좋음 · 잡음 샘플이 0.1% 를 넘으면 나빠짐 → 거르기가 핵심 |
| 최대 | 약 8,000 | 약 10시간 | 더 늘리면 VoxCPM2 특유의 합성 티 · 단조로운 운율을 배울 위험이 이득보다 큼(VoxCPM2 자신도 마지막 학습은 실제 녹음으로만 함) |

- 공식 Qwen3-TTS 단일 화자 FT 안내: **모든 샘플에 같은 ref_audio** 강력 권장 · 예시 lr 2e-6 × 10 epoch(배치 32) 또는 2e-5 × 3 epoch · 데이터 양은 명시 없음.
- 구성(3,000문장 기준): 코드스위치 약 15% · 고객형 긴 문장 약 15% · A7N · 542 일반 문장 약 70%.

### 1-3. 만드는 법
- 코드: [`../../tools/synth_dataset/sref_synth.py`](../../tools/synth_dataset/sref_synth.py) — pick → synth(env voxcpm) → score(q3tts) → asr(q3tts_ser) → filter
- 서비스 ref = `~/workspaces/reference_audios/qwen3tts/set2_trim03_rms20/female_ment_natural_24k_trim03_rms20.wav` + `normalized_text` · seed 1986 · cfg 2.0 · 10 steps · `normalize=False` + ko_tts_norm(qwen3tts) · 준비 합성 1회 · 48kHz → 24kHz
- 자동 거르기: 한글 CER ≤ 10% · 서비스 ref 유사도 ≥ 0.60 · 초당 글자 2.5~9 · 끝 잘림 없음(끝 무음 < 0.05초 그리고 마지막 50ms > −45dB)
- 결과 `~/workspaces/preprocessed/q3tts_koft/SREF/<판>/train.jsonl`(ref_audio = 서비스 ref · speaker = service) → q3tts 에서 `python -m q3ko.data.extract_codes`

### 1-4. 시범 300문장 결과
- 합성 300개 · 실패 0 · 재현 ✅ · RTF 0.30(GPU 1장) → 3,000문장(약 5시간)이면 GPU 1장 약 1.5시간, 4장이면 약 25분.
- 자동 거르기 합격 **223/300(74%)** · 합격분 약 23분.

| 문장 종류 | 합격 | 목소리 유사도 | 한글 CER | 끝 잘림 |
|---|---|---|---|---|
| run117 검수 문장 | 47/50 | 0.86 | 1.5% | 1 |
| 고객형 긴 문장 | 47/50 | 0.87 | 1.5% | 2 |
| A7N 문장 | 46/50 | 0.77 | 1.3% | 0 |
| 542 문장 | 38/50 | 0.80 | 4.7% | 1 |
| 코드스위치 | **45/100** | 0.74 | 15.9% | 2 |

- 떨어진 이유: CER 54 · 목소리 19 · 속도 13 · 끝 잘림 6(겹침 있음).
- ⚠️ 코드스위치 불합격은 **채점기 탓이 많아 보입니다**.
  - whisper 가 영어를 한글로 받아 적거나 붙여 써서 한글 CER 이 올라감.
  - 영어만 있는 문장은 "초당 글자 수" 기준이 맞지 않아 속도로 떨어짐.
  - → 코드스위치는 **청음으로 판정**하고, 기준(영어 문장 속도 · CER 계산)을 고친 뒤 본 합성에 적용.
- 정규화기(qwen3tts)가 일부 영어를 한글로 바꿉니다(QR → 큐알 · pause → 퍼즈 · TV → 티비 · GPS → 지피에스). 서비스 입력과 같은 처리라 그대로 두었습니다.
- 목소리 유사도는 고객형 문장에서 0.86~0.87 로 높습니다(같은 사람 다른 녹음 수준).

## 2. ② 감정 증강(D안) — 다른 목소리로 감정 문장 만들기
### 2-1. 무엇을 하려는가
- q3tts 감정 모델은 감정을 낼 때 ref 목소리를 놓칩니다. 원인 가설: 감정 녹음이 학습 화자 91명 목소리로만 있어 "감정 = 그 사람들 소리"로 배움.
- D안: 감정 문장을 **여러 다른 목소리**로 만들고, 학습 때 ref 는 그 목소리 주인의 **무감정 녹음**으로 → "감정과 목소리는 따로"를 직접 보여 줌.
- 10/28 음성 변환(VC) 7개 모델 시범은 목소리는 바뀌었지만 **감정이 빠졌습니다**(사용자 청음). 그래서 VoxCPM2 로 다시 시도.

### 2-2. 지시 방법 비교(서비스 ref 21문장, `voxcpm2_aug_samples`)
| 방법 | 목소리 유사도 | 감정 맞힘* | CER |
|---|---|---|---|
| M0 지시문 없음 | 0.79 | 33% | 2.0% |
| M1 영어 괄호 지시문(우리 문구) | 0.63 | 44% | 1.4% |
| M2 영어 감정 묘사 | 0.62 | 39% | 14.5% |
| M3 한국어 지시문 | 0.70 | 33% | 2.3% |
| M4 감정 ref 소리(prompt) | 0.40 | 56% | 1.4% |
| (참고) q3tts s2250 | 0.70 | 44% | 1.3% |

*emotion2vec 기준 — 한국어에서 사람 판단과 자주 어긋남(슬픔은 거의 못 잡음). 사용자 청음: M4 감정은 대체로 맞음.

### 2-3. 목소리 섞임 측정(`voxcpm2_D_pilot`, 192개)
- 목표 화자 16명(542 여4 · 남4 + A7N 무감정 보유 여4 · 남4) × 감정 6칸 × 문장 2. prompt = 같은 성별 **다른** A7N 화자의 그 칸 감정 녹음, reference = 목표 화자 무감정 녹음.
- 잣대: 출력이 (목표 화자 진짜 녹음 평균) 과 (감정 ref 화자 진짜 녹음 평균) 중 어디에 더 가까운가.

| 목표 | 무감정 잣대: 목표 쪽 | 목표 유사도 | 감정 ref 화자 유사도 | 공정한 잣대: 목표 쪽 | (대조) 진짜 녹음 |
|---|---|---|---|---|---|
| 542 8명 | **9%** | 0.30 | 0.58 | — | — |
| A7N 8명 | **7%** | 0.43 | 0.62 | **2%** | 100% |

- 감정 ref 소리 자체와 목표 화자의 유사도는 0.29 → 출력(목표 0.30~0.43)은 감정 ref 소리와 거의 같은 거리 = **목표 목소리를 거의 안 따라감**.
- 칸별로도 같음(목표 쪽 0~19%, Sad-B 542 만 38%). 화자별 최고 25%.
- emotion2vec 맞힘 57~60%(분노 88~100% · 슬픔 25~31%).
- **결론**: VoxCPM2 Ultimate cloning 에서 목소리는 사실상 **prompt 소리**가 정하고 reference 는 약하게만 작용합니다. 그래서 M4 는 "다른 목소리의 감정 문장"이 아니라 "**감정 ref 화자 목소리로 새 문장**"을 만듭니다.
  - 앞서 서비스 ref 실험의 0.40 도 "감정 착시"가 아니라 실제로 감정 ref 화자 목소리였을 가능성이 큽니다.

### 2-4. 그래서 쓸 수 있는 것 · 없는 것
| 쓰임 | 가능? | 설명 |
|---|---|---|
| D안(감정 × 새 목소리) | ❌ M4 로는 불가 | 목소리가 안 바뀜 |
| **같은 화자의 감정 문장 늘리기** | ⭕ 후보 | M4 출력 = prompt 화자 목소리 + 그 감정 → A7N 화자별 · 칸별 문장 수를 늘리는 데 씀(정답 목소리 = 그 화자, ref = 그 화자 다른 녹음). 목소리 문제를 직접 풀지는 않음 |
| D안 대안 1: Controllable(M1/M2) + 목표 reference | △ | 목소리는 대체로 유지(0.62~0.70), 감정이 약함 |
| D안 대안 2: **VoxCPM2 를 A7N 감정으로 FT(LoRA/전체)** → 괄호 지시문 + 목표 reference | 후보 | 지시문만으로 감정이 확실히 나오게 만들면 목소리는 reference 로 → vox_koft FT 프로젝트(2026-11-05 지시문 `../../_handoff/20261105_1405_prompt_ft_lora_setup.md`) |
| 무감정 녹음 없는 A7N 61명의 무감정 ref 만들기 | 청음 필요 | §2-5 |

### 2-5. 무감정 ref 만들기 시범(A7N 무감정 없는 화자 8명 × 3문장)
| 방식 | 그 사람 녹음과 유사도 | emotion2vec 무감정 판정 |
|---|---|---|
| CTRL(그 사람 녹음 reference + `(calm, neutral, plain reading voice)`) | 0.65 | 0% |
| ULT(그 사람 녹음을 prompt 로) | 0.72 | 4% |
| (대조) 진짜 녹음끼리 | 0.87 | — |

- 둘 다 같은 사람 진짜 녹음끼리(0.87)보다 낮습니다. emotion2vec 은 한국어 무감정을 잘 못 잡아 0~4% 는 믿기 어렵습니다 → **청음으로 판단**.
