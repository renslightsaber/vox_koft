## 3. 기술 메모
- 실행 예
  ```bash
  ./scripts/run.sh train sft  --exp configs/experiments/sft/A7N100_ref_FT_00_smoke.yaml   --hw rtxpro6000_1gpu --gpu N --smoke
  ./scripts/run.sh train lora --exp configs/experiments/lora/A7N100_ref_LoRA_00_smoke.yaml --hw rtxpro6000_1gpu --gpu N --smoke
  python -m voxko.engine.synth --model <run>/step_N/export_lora --text "…" --emotion Happy-B --ref <무감정 wav> --out x.wav
  ```
- 저장: `step_N/export_ft/`(공식 `from_pretrained` 가 그대로 엶 · bf16 4.6GB) · `step_N/export_lora/`(70MB).
  - 재개용 파일이 있는 step 은 FT 약 31GB, LoRA 약 9GB 입니다. accelerate 가 LoRA 도 모델 전체를 저장하기 때문입니다.
- resume 검사 결과: 끊고 이어도 lr · 데이터 위치 · ref 선택이 완전히 같습니다. loss 차이(≤3e-3)는 끊지 않은 run 끼리의 GPU 비결정성 크기와 같습니다.
- accelerate 포트는 29600 / 29610 / 29620 입니다(q3tts_koft 의 29500 / 29510 / 29520 과 다름).
- ⚠️ 함께 도는 작업의 메모리는 변합니다(SREF 가 GPU 1 에서 8GB → 20.6GB 로 늘었던 적 있음) → 시작 전 `nvidia-smi`. 16:05 KST 에는 4장 모두 비어 있었음.
- 학습 도중 TB 합성(media, 500 step 마다) 경로도 2GPU 에서 확인(FT peak 63.7GB).
- `tools/pre_train_backup.py <exp> --hw … [--accel …]` = 학습 전 백업.
- 검증 중 GPU 4장 모두에서 사용자의 q3tts_koft **SREF 합성**(env voxcpm · 장당 약 7GB)이 돌고 있었습니다. 그래서 GPU 3 · GPU 2,3 을 함께 썼습니다.
- 검증 스크립트(scratchpad · 세션용): `resume_test.sh`(ref vs 끊고 이어서) · `cmp_tb.py`(TB 수치 비교) · `synth_check.py`(원본 · FT · LoRA 합성).
